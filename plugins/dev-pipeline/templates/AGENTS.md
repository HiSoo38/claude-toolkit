# AGENTS.md

이 프로젝트의 규칙은 **[CLAUDE.md](./CLAUDE.md)** 를 따른다. 이 파일은 CLAUDE.md 를 읽지 않는 에이전트(Codex 등)를 위한 안내이며, 내용이 겹치면 CLAUDE.md 가 우선한다.

요약:

- 기술 스택·빌드·테스트 명령은 CLAUDE.md 의 "기술 스택", "빌드·테스트 명령" 섹션에 있다.
- 계약 문서는 `docs/` 에 있고 (경로는 CLAUDE.md "계약 문서" 표), 사람 승인 없이 바꾸지 않는다.
- 작업 하나 = worktree 하나. 할당받은 파일 범위만 수정한다.
- 완료 조건: 빌드 성공 + 테스트 통과 + 리뷰 블로커 0.

## Review guidelines

코드 리뷰 기준이다. dev-pipeline 의 Claude 리뷰, Codex 로컬 리뷰(`/dev-pipeline:review-diff`), GitHub PR 의 Codex 리뷰(`@codex review`)가 모두 이 섹션을 따른다. 프로젝트에 맞게 항목을 더하거나 고친다.

기준 문서: CLAUDE.md 의 기술 스택, `docs/` 계약 문서(requirements, 스키마, api-spec), 구현 계획(`docs/tasks/` — 계획서 `plan.md` 의 공통 약속, 구현 체크리스트 `checklist.md` 의 그 작업 항목, 작업 카드 `T<번호>.md`. 브랜치명 `t<번호>-...` 로 작업을 찾는다).

다음은 **블로커**(머지 금지)로 본다:

- 계획 불일치: 체크리스트 항목이나 카드의 완료 조건 중 빠지거나 반만 된 것이 있다. 계획에 없는 기능을 추가했다. 계획서의 공통 약속(함수·타입 모양)을 어겼다.
- 영향: 바뀐 함수·타입·스키마·응답 형식을 쓰는 다른 기능이 이 변경 때문에 깨지거나 동작이 바뀐다.
- 처리되지 않은 에러 시나리오: 빈 값·경계값·잘못된 입력, 없는 대상, 중복·동시 요청, DB 등 외부 자원 실패에서 잘못된 응답이나 데이터 손상이 난다.
- 계약 불일치: URL·메서드·요청/응답 필드·에러 코드가 api-spec 과, 테이블·컬럼·타입·제약이 스키마와, 동작이 requirements 기능과 다르다. 계약에 없는 동작을 추가했다.
- 보안: 인젝션(쿼리·명령·경로), 권한 확인 누락, 비밀값·개인정보의 하드코딩·로그·응답 노출.
- 데이터 손상 가능성: 함께 성공·실패해야 하는 쓰기가 한 트랜잭션이 아니다.
- 작업 범위 밖 파일 변경, `docs/` 계약 문서를 승인 없이 변경.
- 완료 조건, 바뀐 동작, 위 에러 시나리오에 대응하는 테스트가 없다.
- 코드 중복: 이미 있는 공통 코드(CLAUDE.md "공용 코드 위치", 계획서 "재사용할 기존 코드")를 두고 같은 기능을 새로 만들었다.

다음은 **권장**(머지 가능, 수정 권함)으로 본다:

- 실패 경로를 삼키거나 내부 정보를 그대로 노출하는 예외처리.
- N+1 조회, 페이지네이션 없는 전체 조회, 반복문 안 I/O, 인덱스가 필요한 조회.
- 트랜잭션 안의 외부 호출 등 오래 걸리는 작업.
- 코드 구조 (CLAUDE.md "코드 구조 원칙"): 너무 긴 파일 · 함수, 한 파일에 섞인 여러 책임, 과분리로 흩어진 관련 코드, 주변과 다른 구조 · 이름 · 관용구, 확장하기 어려운 하드코딩. 판단 잣대는 "다른 팀원이 코드만 보고 이해할 수 있는가".

이름·포맷·주석은 **사소함**으로 본다. 확신할 수 없는 지적은 "확인 필요" 를 붙이고, 추측으로 블로커를 만들지 않는다.
