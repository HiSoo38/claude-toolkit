# 리뷰 지시문

`<...>` 를 채워 Codex 와 Claude 리뷰어에게 똑같이 넘긴다.

## 전수 리뷰 (6단계)

```text
저장소 <경로> 의 브랜치 <기능 브랜치> 가 <통합> 에 대해 바꾼 내용 전체를 리뷰해 줘.
범위: git diff origin/<통합>...HEAD (커밋 <n>개를 합친 변경). 커밋별로 나누지 말고 PR 하나로 본다.
계획서: <plan.md 경로>, 체크리스트: <checklist.md 경로>. 프로젝트 규칙: CLAUDE.md · AGENTS.md.

아래를 항목마다 빠짐없이 확인하고, 찾은 것을 이번에 전부 적어 줘. 다음 회차로 미루지 마.
- 버그 (경계값, null, 시간대, 동시성, 낙관적 업데이트 되돌리기)
- 보안 (권한 · RLS 우회, 입력 검증, 열린 리다이렉트, 비밀값 노출)
- 에러 처리 (실패 시 사용자에게 보이는 것)
- 성능 (불필요한 요청 · 렌더, N+1)
- 코드 분리 (이미 있는 공용 코드를 다시 만들었는지, 한 파일이 너무 커졌는지, 과분리)
- 기존 스타일과의 차이 (이름, 폴더 구조, 주석 방식)
- 계획서 · 체크리스트와 구현이 맞는지
- CLAUDE.md 규칙 위반
- (문서면) 단계 번호 · 참조 일관성, 그대로 따라 할 수 없는 지시

형식: `## 꼭 고칠 것` / `## 고치면 좋은 것` / `## 사소함` 세 묶음. 각 지적에 파일:줄과 이유. 한국어.
파일은 고치지 마. 키 · 토큰 · 비밀번호 · 개인 정보는 인용하지 말고 <가림> 으로 써.
```

## 확인 리뷰 (9단계)

```text
저장소 <경로> 의 브랜치 <기능 브랜치>. 1차 리뷰 지적과 처리 결과는 아래 표와 같다.
<판단 표>

범위를 좁혀서 두 가지만 봐 줘:
1. "맞음" 으로 판단해 고친 지적이 실제로 제대로 고쳐졌는지 (git diff <1차 리뷰 시점 해시>..HEAD)
2. 고치면서 새로 깨진 것이 있는지
새로운 개선 제안은 적지 마.

형식: `## 꼭 고칠 것` / `## 고치면 좋은 것` / `## 사소함`, 파일:줄과 이유, 한국어.
파일은 고치지 마. 키 · 토큰 · 비밀번호 · 개인 정보는 <가림> 으로 써.
```
