# 테스트

목표는 사람이 화면에서 확인할 항목을 최대한 줄이는 것이다. 자동으로 확인한 것과 못 한 것을 항목별로 나눠 보고한다.

## 테스트 도구가 없을 때

`package.json` 에 단위 테스트 도구(vitest · jest)나 화면 테스트 도구(@playwright/test)가 없으면:

1. SKILL.md 3 단계의 "질문은 여기서 한 번에" 에 설치 여부를 넣어 묻고 (의존성이 바뀌는 일이다), 답을 계획서 "결정 사항" 에 적는다.
2. 승인되면 [setup.md](setup.md) 의 "테스트 도구 설치" 대로 한다. 거절되면 그 층의 항목을 전부 "사람" 으로 돌린다.

## 단위 테스트 (테스트 먼저)

대상: 계산 · 변환 · 검증 · 권한 판단 · 날짜 처리 · 데이터 가공처럼 입력과 출력이 정해지는 코드. 화면 컴포넌트 안에 이런 로직이 있으면 함수로 빼서(구조 설계에 적는다) 그 함수를 테스트한다.

1. 체크리스트 항목의 동작을 테스트로 쓴다. 파일은 대상 옆에 `<이름>.test.ts` (프로젝트에 다른 관례가 있으면 그것).
2. 실행해서 **실패하는 것을 확인한다** (`han.mjs run "npx vitest run <테스트 파일> --maxWorkers=1"`). 바로 통과하면 테스트가 아무것도 확인하지 않는 것이니 고친다.
3. 구현하고 다시 실행해 통과를 확인한다.
4. 경계값을 넣는다: 빈 값 · null · 0 · 아주 큰 값 · 시간대 경계 · 권한 없는 사용자.

DB · 네트워크를 부르는 코드는 그 경계(조회 함수 · API 클라이언트)를 가짜로 바꿔 테스트한다. 실제 DB 에 붙는 테스트는 쓰지 않는다.

## 화면 자동 테스트

설정의 `화면 테스트` 범위를 따른다.

| 범위 | 자동으로 하는 것 | 사람에게 넘기는 것 |
| --- | --- | --- |
| `조회만` (기본) | 페이지 열기 · 이동 · 목록 · 상세 · 필터 · 빈 상태 · 에러 화면 표시 확인 | 저장 · 수정 · 삭제가 필요한 항목 |
| `테스트 계정` | 설정의 테스트 계정으로 로그인해 그 계정 데이터 안에서 쓰기까지 | 다른 계정 · 운영 데이터에 닿는 항목 |
| `로컬 DB` | 로컬 DB 에 붙은 dev 서버에서 전부 | 없음 (외부 서비스 연동만) |

순서:

1. 자원 예산의 `화면 자동 테스트` 가 `건너뜀` 이면 여기서 끝내고 해당 항목을 사람 확인으로 넘긴다.
2. "화면" 항목의 Playwright 테스트는 SKILL.md 6 단계에서 그 항목과 함께 써 둔다 (빠졌으면 여기서 쓰고, git 모드면 `test(e2e): …` 커밋으로 올린다): `e2e/<작업-이름>.spec.ts` (프로젝트 관례가 있으면 그것). 테스트 이름에 체크리스트 번호를 넣는다 (`1. 목록에 새 항목이 보인다`).
   - `조회만` 이면 폼 제출 · 삭제 클릭 · 쓰기 요청을 넣지 않는다.
   - 로그인이 필요한 화면은 설정의 `로그인 세션 파일` 이 실제로 있거나(소셜 로그인 프로젝트) 테스트 계정이 있을 때만. 둘 다 없으면 그 항목은 사람 확인으로 넘기고, 보고에 세션 저장 방법([setup.md](setup.md) "테스트 도구 설치")을 한 줄 적는다. 계정 값은 환경변수에서 읽고 파일에 쓰지 않는다.
   - 실패를 찾기 쉽게 실패 시 스크린샷을 남기는 설정을 쓴다.
3. `han-pipeline:tester` 에이전트를 부른다 (루트, 테스트 파일, dev 서버 주소, 범위, han.mjs 경로, 체크리스트를 넘긴다). 직접 Playwright 를 돌리지 않는다.
4. tester 결과의 ❌ 는 코드를 고치고 `check` 후 tester 를 한 번 더 부른다. 두 번째도 실패하면 사람 확인으로 넘기고 원인 추정을 보고에 적는다.

## 보고 형식

```markdown
## 테스트 결과
- 단위 테스트: n개 추가 · 전부 통과 (`<파일들>`)
- 화면 자동 테스트: n개 중 n개 통과

| 체크리스트 | 확인 방법 | 결과 |
| --- | --- | --- |
| 1. … | 단위 | ✅ |
| 2. … | 화면 자동 | ✅ |
| 3. … | 사람 | ⬜ 직접 확인 필요 — <어디서 무엇을 하면 → 무엇이 보여야 함> |
```
