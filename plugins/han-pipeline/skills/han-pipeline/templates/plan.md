## 체크리스트

모드: git / 로컬 · 브랜치: <이름 또는 지금 브랜치> · PR: (만든 뒤 링크)

### 구현

항목마다: 테스트 먼저 → 구현 → `check` 통과 → `[x]` (git 모드면 커밋 · push). PR 은 아래 리뷰 칸에서 기능 끝에 한 번.

- [ ] 공용: … (구조 설계의 새 공용 코드) — 테스트: 단위
- [ ] DB: … (마이그레이션 파일명) — 테스트: 사람 (적용은 사람)
- [ ] 로직: … — 테스트: 단위
- [ ] 화면: … — 테스트: 화면

### 테스트

- [ ] 단위 테스트: n개 통과
- [ ] 화면 자동 테스트: n개 중 n개 통과 (또는 건너뜀 — 이유)
- [ ] 직접 확인 목록 정리

### 리뷰 (git 모드)

- [ ] 진행 문서 갱신 · 최신 통합 브랜치 반영 · PR 생성
- [ ] 전수 리뷰 (<리뷰어 · 영역별로 나눴으면 영역>): 요구사항 대조 됨 n · 안 됨 n / 꼭 고칠 것 n · 고치면 좋은 것 n · 사소함 n → 처리 결과
- [ ] 지적 반영 커밋 · 리뷰 지적 기록
- [ ] 확인 리뷰 (<리뷰어>): 결과 — 1차에서 꼭 · 좋음을 고쳤을 때만, 아니면 "건너뜀"
- [ ] 리뷰 요약 코멘트
- [ ] 통합 브랜치 머지
- [ ] 통합 → 배포 PR 생성 · 갱신

### 리뷰 (로컬 모드)

- [ ] reviewer 리뷰 1번: 꼭 고칠 것 n → 처리 결과
- [ ] 커밋 나눔안 보고
